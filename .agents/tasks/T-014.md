# T-014 — SEO: meta dentro del `<head>` en listado/categorías

**Estado:** done · **Dueño:** supervisor · **Abierta:** 2026-10-28

## Objetivo
Lighthouse reportaba `meta-description` = 0 (SEO 92) en `/cool-wallpapers`:
las rutas dinámicas emiten `<title>`/`<meta description>` después de cerrar el
`<head>` (streaming del App Router). Hacer que las URLs indexables rendericen
metadatos dentro del `<head>` real.

## Alcance
- `app/cool-wallpapers/page.tsx`: sin `searchParams` → ruta `○ Static`;
  el servidor pre-renderiza siempre página 1.
- `app/[category]/page.tsx`: `generateStaticParams` (30 categorías) → `● SSG`,
  respetando `dynamicParams` por defecto (categoría desconocida → `notFound`).
- `components/CategoryBrowser.tsx`: `?page=N` se lee tras montar desde
  `window.location` (sin `useSearchParams` para no caer en bailout CSR/CLS);
  la paginación por click mantiene estado local + `router.replace`.
- `tests/e2e/smoke.spec.ts` caso 3: espera el cambio post-hidratación
  (`expect.poll`) en vez de una lectura única.

## Fuera de alcance
- `/search` y `/random` siguen dinámicos (nota y posible `noindex` en otra tarea).
- Cambios visuales o de routing distintos a `?page=N`.

## Verificación
1. `npm run build`: `/cool-wallpapers` `○ Static`, `[category]` `● SSG` (30).
2. `npm run test:e2e` 13/13.
3. Lighthouse desktop (todas las categorías) en listado, categoría y detalle:
   100×4 de cada una + CLS 0.
